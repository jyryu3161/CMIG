## 2. 기능적 문제 (현재 코드 기준, file:line 확인)

### 🔴 High — 제품 사용성

**P-1. GUI 런처 부재.** `cmig/gui/app.py`는 `build_main_window()` 팩토리만 노출하고
`QApplication(...).exec()`·`cmig/gui/__main__.py`가 없으며, `pyproject.toml`의 console script는
`cmig = cli.main:main` 하나뿐이다(비-test 코드에 `QApplication` grep 0건). 설치 사용자는 README의
Qt heredoc을 직접 작성해야만 데스크톱 앱을 켤 수 있다. **제품의 "실행 가능성" 최대 격차.**
→ 수정: `[project.scripts] cmig-gui = "cmig.gui.__main__:main"` + QApplication 부트스트랩 추가.

### 🟠 Med

**P-2. `solve_host` viable 계약 불일치 (mislabel).** `core/host.py:436`이 성공 리턴에서
`viable = biomass > 1e-9`로 재유도한다. 그러나 계약(dataclass/함수 docstring)과 :417의 정답
`viable = status == "optimal"`은 **maintenance 충족 = viable**로 정의한다. maintenance는 만족하나
biomass 최적이 0인 host(영양 제한 하 생존·비성장)를 **viable=False로 오표기**하고, 그 값이
`host_impact.host_viable`·`run_host_microbe`로 전파된다. **LATENT**(toy는 성장 → 테스트 green).
→ 수정: `HostSolveResult(viable, …)`(:417 값 재사용, 이미 True). 1줄.

**P-3. `cmig sweep` run_hash 캐시 미배선 (§10 G4 "캐시 필수" 위반).** `cache_hit`이 성공/실패 모두
`False` 하드코딩(`cli/main.py:3641,3674`), `FileSystemStore`/`RunHashCache` 조회 없음 →
동일 run_hash 조건도 매번 full MICOM 재solve. 라이브 확인: sweep-fixture의 cache_hit 전부 False.
provenance·실패기록은 충족, **재계산 회피만 미구현.**

**P-4. Advanced GUI 탭이 inert 스텁.** Community Builder(`builder.py:37`, run/preview·gate UI 없음),
Medium Editor(`editors.py:27`, Check Growth·minimal medium·before/after 없음),
Sweep View(`views.py:57` `run_sweep` 미호출), Scenario Compare(`builder.py:171` `load_comparison` 미호출)가
탭에 도킹되나 어떤 액션에도 연결되지 않고 "CLI를 쓰라"고 안내한다. G1 constraint-sandbox의 debounce
QTimer(`builder.py:132`)도 connect/start 안 된 dead code.

**P-5. GUI 워커의 argparse `SystemExit` 미포착.** GUI 워크플로가 스레드에서 `cli.main.main(argv)`를 호출하는데,
argparse 거부 시 `SystemExit`(BaseException)는 `JobRunner._run`의 `except Exception`에 안 잡혀
job이 DONE/FAILED로 전이 못 함 → 버튼 재활성·에러 표기 없이 UI 잠김. 트리거 확률 낮음(위젯이 argv 구성).

**P-6. minimal medium MILP 비결정성 + U-base 왜곡 (구 F-8 미해소).** `core/medium.py:120`이
`minimal_medium(minimize_components=True)`를 secondary objective 없이 호출 → equicardinal 대안 최적 중
선택이 solver 의존(출력 sort만). `_apply_min_medium_invariants`가 MILP 후 {H₂O,H⁺,Pi} 강제추가로
`n_components` 부풀리고 `limiting_nutrients`가 이를 essential로 오라벨(lb=0인 U-base 포함). **LATENT.**

**P-7. namespace gate 기본 무력 + model-review "blocked" 오해 유발 (구 F-4).** `model-review`는
`blocked: true, coverage 0%`를 보고하지만, community 경로(strain-growth/search/…)는 decision 기본값 `[]`로
게이트를 통과한다(라이브 확인: 정상 solve). 즉 사용자엔 겁주는 신호이나 비구속이고, **혼합 namespace
풀에 대한 실보호력은 0**이다. 자동 정합 producer가 필요하거나, 최소한 model-review 문구를 완화해야 한다.

### 🟡 Low
- `diagnostics.from_exception`이 `*UnavailableError`(capability 부재)를 `CAPABILITY_MISSING` 아닌
  `SOLVER_ERROR`로 분류(`diagnostics.py:47`) — sweep 실패 분류 정밀도(구 C-2 잔여).
- OSQP golden run_hash가 fixture는 4-dec, production은 6-dec(`golden_fixture.py:92` vs `solve_output.py:128`)
  → osqp golden run_hash ≠ 사용자 실측치(무해하나 C-1 테스트 추가 시 실패).
- 단일-GEM `flux_variability`가 osqp 미거부(community FVA는 거부) — `fva.py`.
- JobRunner: unknown job_id → bare `KeyError`; job dict eviction 없음(장수 세션 누수).
- Gurobi "Academic license…" 배너가 **stdout**으로 출력 → 스크립트 파싱(명령치환) 오염 가능(본 평가에서 실제 발생).
- "Export Figure"는 사전 생성 SVG의 `shutil.copyfile`(포맷/저널 프리셋 선택 없음).

### 리뷰 발견의 정직한 재조정 (구현 중 발견)
- **P-2 (host viable)**: 코드를 뜯어보니 `test_host_feasible_zero_objective_is_not_viable` 가
  "optimal but biomass=0 → viable=False" 를 **의도적으로 고정**하고 있고, 세 solve 경로(216·331·436)가
  모두 `objective>1e-9` 로 일관된다. 즉 원래 M-1 권고(`viable=status=="optimal"`)는 **테스트와 설계 결정을
  깨뜨린다.** 진짜 결함은 계약(docstring)이 "maintenance=viability" 라 오기재한 점 → **docstring/계약을
  실제 tested 거동(feasible AND biomass>0)에 맞게 수정**했다. 거동 변경 없음.
- **P-6 (minimal medium)**: `test_limiting_nutrients_are_components` 가 `limiting==components` 를,
  `test_tc10_u_base_always_included` 가 `U-base⊆components` 를 **명시 계약**으로 고정한다. limiting_nutrients
  를 subset 으로 바꾸면 계약 위반. 안전·정확한 부분(**흡수 용량 0 인 U-base 를 강제 추가에서 제외** →
  essential 오라벨 방지)만 구현하고, cross-solver 대안최적 tie-break 는 cobra API 한계로 **docstring 에 정직
  명시**했다(`test_zero_uptake_u_base_excluded_from_medium` 신규).
- **교훈**: adversarial 리뷰 발견은 테스트/설계와 대조 없이 그대로 적용하면 안 된다. 두 건 모두 라이브
  구동+테스트 확인으로 "false-positive(계약 오해)" 임을 밝히고 실 결함만 수정했다.
