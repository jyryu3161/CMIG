## Scientific implementation contract — lane A

### A1. Identifiability and null semantics (SC-01)

Keep optimal solver status distinct from identifiability. Add nullable point and range/identifiability fields to `HostArm` and `HostKoDelta`; append defaulted fields to preserve existing constructor compatibility. Use the upstream `HostImpact.microbe_to_host_ranges`, `ambiguous_metabolites`, and normalized metabolite lookup. The sparse positive-only point dictionary is not evidence that an absent target equals zero.

| State | Point | Interval | Delta / ranking behavior |
| --- | --- | --- | --- |
| Optimal, finite collapsed interval `[x,x]` within the existing identification tolerance | finite `x`, including exact `0` | retain interval | point comparison permitted |
| Optimal, noncollapsed finite interval | null | retain `[lo,hi]` | point delta null; transfer/weighted fitness unevaluable |
| Solver failure or unavailable/untrustworthy FVA/readout | null | null unless a separately valid range exists | no numerical target claim; retain reason and actual statuses |
| Target absent from sparse point map | inspect range and structural evidence | as supported | do not infer zero merely from absence |

A structurally zero transfer can be `[0,0]` only when solved coupling proves no microbial availability/route for that target, or upstream records a zero interval. A target absent because namespace matching failed stays explicitly unmatched; do not turn it into a valid zero measurement. Distinguish `unavailable`, `ambiguous`, and `identified` with an explicit reason/state. Retain objective readouts when target attribution is ambiguous.

Keep legacy `comparable` as objective comparability (both relevant solves optimal and objectives finite); add explicit objective/target comparability and per-metabolite identifiability so its meaning cannot imply that all deltas are numbers. Emit point metabolite deltas only for two identified points. Preserve an ambiguous metabolite in range/diagnostic output instead of omitting its existence. Optional interval differences use **`[arm.lo − baseline.hi, arm.hi − baseline.lo]`**, labeled conservative marginal bounds across separate arms, not paired FVA, confidence intervals, or a proven jointly achievable change interval. Null intervals never participate in subtraction. Existing direct callers that explicitly supply a finite `target_transfer` still supply a point assertion; an omitted metabolite in a sparse dictionary is not such an assertion. Update legacy test fixtures to supply explicit zero/range evidence where their intended biological scenario requires it, not to retain the defective default-zero inference.

`host-search-bigg --metric objective_value` may rank an optimal finite objective with ambiguous transfer, retaining the null transfer and warning. `target_transfer` and `weighted` must exclude such candidates from numeric ranking, preserve their objective/ranges in the evaluation ledger, and report no evaluable winner if all scores are unavailable. Do not introduce an implicit midpoint, lower-bound, or optimistic interval policy. Existing weighted positive references/weights remain required.

Propagate through KO JSON/CSV, host-search JSON/CSV, terminal formatting (currently `float(...)` in multiple writers), figures, summaries, manifest status and GUI adapters. JSON uses `null` and CSV uses blank unavailable numeric cells, accompanied by range/status columns. Genuine zero remains `0`, not blank. A KO with valid objective deltas but missing requested target deltas is degraded, not failed solely because attribution is ambiguous. Invalid/nonviable/cancelled outcomes retain their existing distinct semantics.

Acceptance: reuse audit appendix C as actual LP/FVA; cover `[0,5]→[5,5]`, reverse arms, both ambiguous, `[0,0]`, structurally absent versus unmatched, namespace-normalized spelling, failed arm, and ordinary identified points. Exercise all three host-search metrics end to end at the CLI serialization boundary; the prior audit did not run this CLI end to end. Assert nulls/ranges and partition/status, not just warnings.

### A2. Boundary identity, orientation and community hidden supply (SC-02–04)

Use a small shared adapter in `core/boundary.py` or a new `core/exchange.py`, not independent name heuristics. For a one-metabolite boundary reaction with coefficient **`c`** and raw reaction flux **`v`**:

- Model supply/uptake amount is `max(c*v, 0)`; the signed environment amount is **`q = −c*v`** (`+` secretion, `−` uptake).
- A physical uptake cap `U` becomes the corresponding raw reaction bound `U/abs(c)`, in the supplying direction. Transform both FVA endpoints before sorting and clamping to nonnegative uptake; a reverse exchange or interval crossing zero must work.
- Strip only the actual compartment spelling from the actual metabolite ID, preserving stereochemistry and the existing namespace gate. A reaction name is only a source identifier, never chemical identity.
- Reject zero/nonfinite coefficient, unresolved identity, and unsupported multi-metabolite boundary interpretations with named reactions before a successful scientific result. Do not guess a nutrient from the first metabolite of an ambiguous reaction.

**Compatibility constraint:** current `boundary.supply_capacity`, `set_supply_limit` and `MediumSpec` follow COBRA reaction-flux bound semantics. Do not globally redefine those helpers or multiply every medium limit by a coefficient. Add explicit amount-coordinate conversions where dFBA concentrations and host physical availability/readouts require them; document the basis. Unit-stoichiometry behavior stays unchanged. For single-model dFBA, configured `vmax` is a physical amount rate and inferred `vmax` comes from the supplying capacity times `abs(c)`; use `q` consistently for concentration integration, depletion clamp, and reported managed-exchange fluxes. Model bounds must restore on completion/failure.

Host coupling must convert physical microbial/background availability into raw bounds and back into physical FVA/readout amounts consistently. Normalize `InterfaceFlux.flux` before classifying it so its sign agrees with its label; if raw reaction flux is retained for debugging, name it separately. Audit `classify_host_exchanges` and all `_uptake_fva_ranges` callers, not only the two reproduced lines.

For MICOM member exchanges, read **community topology**: actual shared pool metabolite, associated member, reaction and flux-table row/column. MICOM member→pool reactions have two sides and are no longer members of `community.boundary`; do not close these legitimate transfers as hidden supplies. The table's member flux is per-member biomass, while the pool coefficient already contains abundance. Convert an oriented raw flux to a per-member secretion amount using the pool coefficient divided by the actual positive member abundance; multiply by abundance **once** for the environment balance. Aggregate physically additive exchanges for the same member/metabolite instead of overwrite/first-match. Verify all required flux cells are finite and present; absence of a cell is not zero.

Static inspection of installed MICOM 0.39.0 `community.py:__add_exchanges`/`__update_exchanges` and `solution.py` confirms that `global_id`/`community_id` identify grouped flux-table cells and pool coefficients use ±abundance. This is an **existing, version-specific coupling**, also present in `dfba_community._member_flux_keys`, despite the root spec's public-API-only wording. Isolate and document this adapter dependency with version/shape checks and focused golden tests; do not invoke private MICOM methods. Flag this contract tension in Astra review rather than claiming it is a documented stable public API.

MICOM also constructs member pool coefficients as ±abundance without preserving an arbitrary original exchange magnitude. Therefore a readout-only multiplication cannot repair a non-unit input exchange's physical mass balance. The bounded safe behavior is: fully support non-unit one-metabolite exchanges in standalone dFBA/host conversion; **reject unsupported non-unit community input exchanges before MICOM construction/solve with a clear compatibility diagnostic**, unless the implementer demonstrates a documented MICOM representation that preserves the physical amount. Do not normalize/write source GEMs or patch MICOM's private community assembly. This limitation must be disclosed, and unit/reverse-unit community cases must pass. This is a source-derived integration risk, not a newly executed non-unit MICOM reproduction.

For medium translation: an exact input reaction ID may select that verified exchange; canonical source forms can resolve by actual metabolite identity. Preserve equal-alias merge and conflicting-limit rejection. If multiple target exchange reactions share the nutrient and the source does not identify one unambiguously, reject with candidates instead of `setdefault` selection or opening all and multiplying availability. Update `effective_medium_by_metabolite` and pool diagnostics/model-import summary as needed so a renamed exchange does not produce inconsistent downstream diagnostics. Do not admit intracellular sink/demand reactions as ordinary external nutrient aliases.

For community dFBA: apply the common all-boundary isolation policy to the actual MICOM community before integration, keeping declared tracked environmental suppliers. Enumerate internal sinks/demands as well as external exchanges, respecting the existing **explicit formula `X` non-exchange pseudo-supply exception**; missing formula is not that exception. Forced undeclared supply with `close_untracked_uptake=True` must reject isolation explicitly (no silent bound relaxation). With closure off, retain and report realized supplying boundary fluxes from the same integrated solution, keyed by unique reaction/member identity and with their biomass basis; mark acceptance uninterpretable. Do not re-solve solely for diagnostics, sum per-member and environment rates as if they have the same basis, or include exempt pseudo-process supply as material uptake. A small additive `SolveResult` boundary-supply readout is preferable to leaking live solver/model objects into results. If required boundary fluxes cannot be read, fail/degrade acceptance; an empty diagnostic is not proof of isolation.

Acceptance: actual MICOM hidden negative sink and positive supplying demand; closure on/off; forced supply rejection; explicit formula-X exception and missing-formula control. Ordinary no-sink control remains stalled at zero substrate. Actual single dFBA/host forward/reverse/non-unit models yield equivalent physical depletion/caps, objective, uptake ranges and labels, including adaptive final-step exhaustion. Renamed `EX_glc__D_e`/`EX_carbon_e`/`carbon_exchange` models preserve member/environment/tidy glucose and abundance-weighted conservation; donor/consumer mixed naming must retain cross-feeding. Test duplicate exchange ambiguity and legitimate aggregation. Run existing golden/sign/namespace/isolation suites without loosening tolerances.
