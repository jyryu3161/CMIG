Q: Are the deferrals defensible as a set?
A: The five ON the list are, individually and as a set. `edges.parquet.weight` is
   the only one a publishing researcher could be harmed by, and the reasoning for
   deferring the VALUE (re-blessing a frozen golden on both solvers, two reviewers
   proposing incompatible `abundance is None` contracts, neither patch scaling the
   FVA bounds) is sound, with a unit disclosure landed in the manifest and echoed
   by inspect-run. I would not have closed it in this pass either.
   THE PROBLEM IS NOT THE LIST, IT IS WHAT IS ABSENT FROM IT. The three P0s in
   section 2 are not on it, and the report's "three separate sites" sentence reads
   as a complete enumeration of the class. Two of the three write publication
   artifacts. That is the gap.

Q: Is the run_hash / result_digest split documented where a user will meet it?
A: At the point of use, YES and well: `inspect-run` prints "(certifies the
   INPUTS)" and "(certifies the ARTIFACT BYTES)" inline, and the mismatch message
   is the clearest sentence in the codebase. In the reference docs, NO —
   `result_digest` appears in CHANGELOG.md (5×) and nowhere in README.md, docs/,
   or .claude/skills/cmig-metabolic-analysis/SKILL.md. SKILL.md tells an agent to
   run `inspect-run --format json` as the mandated verification step (line 55)
   without telling it that `status` and the exit code both ignore
   `result_digest.match` (P1-b). That combination is how a verification step
   passes a tampered run.

Q: Does the GUI now tell the same truth as the CLI?
A: In the places specifically fixed, yes, and properly. The CC-6 dFBA fix is real:
   `load_dfba_summary` reads `warnings` and `n_untracked_uptake`, flags the status
   cell rather than printing plain "completed", and the `--close-untracked-uptake`
   control is exposed (views.py:183, wired at app.py:1241) so the user can make
   the run interpretable instead of only being told it is not. The CC-8 argv race
   fix is correct. strain-growth's GUI table honestly renders an em dash where the
   figure fabricates a zero.
   Outside those places the pattern recurs. The GUI displays
   `dfba_timecourse.svg`, which carries none of the warning it just rendered
   (P2-d). The results table is built from `top_ranked` only (gui/app.py:1780), so
   gene-KO `unevaluated` rows reach the user only as a forwarded warning string.
   The honest answer is "in the places that were specifically fixed", and the
   remaining gaps are figures and side-partitions rather than numbers.
