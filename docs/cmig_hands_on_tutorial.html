2. Community solve

A 3-member community (iYO844, iHN637, iSFV_1184 from the bundled methods-demo pool) on the literature-grounded AGORA Western gut overlay. The taxonomy CSV has three columns: id,file,abundance.

uv run cmig solve --taxonomy demo/taxonomy.csv \
  --medium medium_presets/gut_overlay_agora_western.csv \
  --allow-unknown-medium --assume-bigg-namespace \
  --solver gurobi --out runs/solve_demo
solve 완료 (solver=gurobi, medium=custom) → runs/solve_demo
  run_hash: a06d5799f3af3f8f…  growth: 0.1502
Medium semantics. --medium is a merge overlay: anything the file does not name keeps the model default. --exact-medium instead isolates the whole boundary and opens only the named exchanges. The manifest records which mode ran (medium_application_mode), so the two can never be confused. --allow-unknown-medium was needed here because the shipped overlay carries background-closure rows for the full 5-model pool; the run is honestly marked degraded with the dropped ids recorded. Overlay rows are tagged row_role=nutrient|pool_closure so exact-mode users can strip the pool-specific block (see medium_presets/PROVENANCE_gut_media.md).

3. Inspecting a run

Every run directory carries a manifest. inspect-run prints what the run was, what certifies it, and how to read its artifacts:

uv run cmig inspect-run --run-dir runs/solve_demo --format text
run_dir: /private/tmp/claude-501/-Users-jaeyongryu-Projects-CMIG/834ec48a-1fea-42bd-9b31-b1e97e50851f/scratchpad/tutorial/runs/solve_demo
kind: community_solve
status: degraded (source: derived)
summary_file: manifest.json
run_hash: a06d5799f3af3f8f734a3e48449ae55779a09e555bc8d050d2631d90ba9e370a   (certifies the INPUTS)
result_digest: not recorded (cmig solve writes a manifest_scope=solve manifest and never emits a result digest; only the workflow manifest kinds do)
edges.weight basis: community_abundance_weighted [mmol gDW_community^-1 h^-1]
  Since tidy 1.3, edges.weight is community-basis (abundance-weighted; do NOT multiply by abundance again). Reconstruction, per metabolite: take only edge_type in {secretion, uptake} (cross_feeding rows are an allocation, not a measured exchange, and must be excluded); give each row the sign of its direction (+ for secretion, - for uptake); the sum equals that metabolite's profile.net_flux. Tidy <= 1.2 artifacts carried the old per-taxon basis (weight_basis: per_taxon_unweighted).
artifacts:
  - edges.parquet
  - manifest.json
  - nodes.parquet
  - profile.parquet
run_hash certifies the inputs (11 frozen components); result_digest, where present, certifies the answer bytes. Note the printed edges.weight basis: since tidy 1.3 the edge weight is already community-basis — never multiply it by abundance again.

4. Model-pool search

Which 2-member combination from a folder produces the most acetate? Small spaces are solved exhaustively; above --exhaustive-max (default 100) a deterministic GA takes over (--ga-* options, ga_metadata in the summary).

uv run cmig search --model-dir demo/pool --target ac \
  --min-size 2 --max-size 2 --solver gurobi --out runs/search_demo

5. Pair: mono vs co-culture (round 8)

The synthetic acetate-producer / butyrate-consumer pair, on two exact media. Interaction deltas are medium-controlled: the community's effective offer is projected onto each monoculture leg, so a difference can no longer be an artifact of each model's native SBML medium.

uv run cmig pair --taxonomy demo/pair.csv \
  --per-medium demo/glucose.csv,demo/acetate.csv --exact-medium \
  --assume-bigg-namespace --solver gurobi --out runs/pair_demo
medium=glucose mode=exact_boundary_isolation: interaction=mutualism (MRO=0, MIP=1)
  producer: mono=10  co=10
  consumer: mono=0  co=10
medium=acetate mode=exact_boundary_isolation: interaction=neutralism (MRO=0, MIP=0)
  producer: mono=0  co=0
  consumer: mono=5  co=5

On glucose the consumer only grows in co-culture (fed by the producer's acetate) → mutualism; on acetate both are independent → neutralism. Outputs include per-condition MRO/MIP, a cross-feeding summary (explicitly labelled shared-pool co-occurrence, not a measured pairwise transfer), and a long-format matrix.parquet across media.

7. Comparing two runs (round 8)

cmig delta is the CLI counterpart of the GUI Compare tab. Here: the same 3-member community on the Western vs the high-fibre overlay:

uv run cmig delta --baseline runs/solve_demo --variant runs/solve_hf \
  --out runs/delta_demo
delta complete (49 significant) -> runs/delta_demo
  community growth_delta: -0.00395

It verifies each input run's recorded digest before comparing and refuses a mismatch, so a delta can never silently compare tampered artifacts.

8. Dynamics: well-mixed dFBA

uv run cmig dfba-fixture --out runs/dfba_demo        # built-in demo
# real usage:
uv run cmig dfba --model my_model.xml --t-end 8 \
  --close-untracked-uptake --out runs/dfba
dFBA: status completed | final_t 1.0 | final_biomass 0.02309 | timepoints 11
final concentrations: {EX_glc__D_e: 9.8502}
Always pass --close-untracked-uptake for a substrate/Km experiment — without it an untracked nutrient can silently feed the model and the run is not interpretable. Check the endpoint with cmig dfba-sensitivity before publishing it. A library-level community dFBA prototype (cmig.core.dfba_community.run_community_dfba) landed in round 8: per-member biomass over a shared pool, Gurobi-only, no CLI surface yet.

9. Host-microbe coupling

uv run cmig host-fixture --out runs/host_demo        # toy 2-interface demo
# real usage (BiGG-style host, e.g. Recon3D):
uv run cmig host-microbe-bigg --host Recon3D.xml --model-dir models/ \
  --target ac --microbial-biomass-gdw 57 --host-biomass-gdw 70 \
  --biomass-basis-kind literature --biomass-basis-source "..." \
  --assume-bigg-namespace --out runs/host
HOST (toy fixture): status optimal | viable True | biomass 35.0
lumen_uptake:    {ac: 8.0, but: 4.0}
microbe_to_host: {ac: 8.0, but: 4.0}
Real hosts require a reviewed interface map (cmig host-map → review → --interface-map); coupling refuses unreviewed annotation matches by default because they can pair chemically distinct D/L stereoisomers. Since round 7, lumen/blood sides are classified from recorded evidence (never guessed from a generic e compartment), and reviewed maps may carry side-aware {"host_exchange", "interface"} entries.

10. Parameter sweeps

uv run cmig sweep-fixture --tradeoff-fs 0.3,0.5 --solvers gurobi \
  --out runs/sweep_demo                              # built-in demo
# real usage — six axes, run-hash cached:
uv run cmig sweep --taxonomy tax.csv --mediums m1.csv,m2.csv \
  --tradeoff-fs 0.3,0.5 --solvers gurobi --assume-bigg-namespace \
  --out runs/sweep
SWEEP: n_runs 2 | metric growth | status ok
sweep.parquet rows: condition value/status per combination (cached by run hash)

Feed the result to cmig stats-sweep --sweep runs/sweep/sweep.parquet for distribution summaries; inferential statistics are gated on real replicates.

11. GUI tour

12. Reading results correctly

WhatRule
run_hashCertifies the 11 frozen input components. Two runs with the same hash asked the same question — it does not certify the answer bytes.
result_digestWorkflow-manifest kinds record it over the answer artifacts; inspect-run verifies integrity.
edges.parquet.weightSince tidy 1.3: community-basis (abundance-weighted) magnitude. Sign lives in edge_type; exclude cross_feeding rows and sign by direction to reconstruct profile.net_flux. Do not multiply by abundance again.
status: degradedThe run continued under a disclosed compromise (e.g. dropped medium ids). The diagnostic names it — report it, don't hide it.
exit codes0 ok · 2 input error · 3 completed-but-failed science (--allow-failed-run can soften 3 to 0 where accepted, never the recorded status).
