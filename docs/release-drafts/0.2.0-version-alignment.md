## Run-hash consequence

`CMIG_CORE_VERSION = __version__`, and the core version is an input to CMIG run hashes. Bumping
`cmig/__init__.py` therefore intentionally moves run hashes even when scientific inputs are
otherwise unchanged. Treat this as a release-wide reproducibility migration:

1. update the version strings together;
2. regenerate `uv.lock`;
3. run `uv run cmig golden verify-envelope` and the run-hash tests;
4. run `uv run cmig golden verify` in the licensed environment;
5. follow the repository's documented golden/schema re-blessing procedure for every expected hash
   change—never patch frozen hashes until the component diff is reviewed;
6. re-run and archive `docs/PUBLICATION_VALIDATION.md` on the release commit.

The non-hashed `boundary_isolation_policy` and `host_isolation_policy` markers still matter: the
new package version separates releases, while those markers identify which scientific isolation
semantics produced an answer.

## Proposed CI guard

Add a small standard-library script such as `scripts/check_release_versions.py` and run it in the
CI quality job immediately after `uv lock --check`. The guard should:

1. read `project.version` with `tomllib` from `pyproject.toml`;
2. read `cmig.__version__` without importing optional solver/GUI modules;
3. parse `CITATION.cff`'s top-level `version` and require `date-released` for a tagged build;
4. parse `.zenodo.json` and require a top-level `version`;
5. parse `.claude-plugin/marketplace.json` and compare `metadata.version`;
6. locate the `name = "cmig"` package in `uv.lock` and compare its version;
7. on a `vX.Y.Z` tag, require the tag text, every metadata value, and the finalized changelog
   heading to equal `X.Y.Z`.

Suggested CI invocation:

```bash
uv run python scripts/check_release_versions.py
```

The script should print every source/value pair before failing so a mismatch is actionable. Unit
tests should cover a missing Zenodo version, the current unrelated marketplace `1.0.0`, a stale
lock entry, a tag/version mismatch, and a release-date placeholder.

## Release order

1. Merge all code/docs tracks and freeze the intended release commit.
2. Apply the aligned metadata and finalized changelog in one reviewable release commit.
3. Regenerate the lock and run the version guard plus all license-free CI gates.
4. Run licensed golden/full-test/publication gates.
5. Build and inspect artifacts only from that commit, then sign the matching `v0.2.0` tag.
6. Add the minted Zenodo DOI to `CITATION.cff` only after Zenodo assigns it.
