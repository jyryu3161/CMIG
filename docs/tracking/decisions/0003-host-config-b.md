# 0003. 숙주-미생물 결합은 CMIG 소유 2단계(구성 B)로 한다

- 상태: 수락
- 날짜: 2026-06-01 (명세 §12 spike 결정)

## 맥락

명세는 (A) MICOM 안에 유지 목적의 숙주를 넣는 방식과 (B) CMIG가 미생물 커뮤니티와 숙주를 따로 푸는 2-compartment 방식 중 spike 후 결정하도록 했다. 확인 결과 MICOM 0.39.0의 `Community.__init__`에는 host 인자가 없어 (A)는 public API로 불가능했다.

## 결정

구성 B: MICOM으로 미생물 커뮤니티를 푼다 → 환경 분비를 lumen 가용량으로 변환 → cobra 숙주 모델을 lumen 흡수 한계와 viability 제약(유지 ATP 등 하한) 아래에서 따로 푼다 → 전달량을 분해한다. 숙주는 커뮤니티 성장 목적에 들어가지 않는다. 경계면은 lumen(미생물 공유)과 blood(숙주 전용) 둘이다. 숙주 구현은 특정 Human-GEM에 묶이지 않고 lumen/blood 경계면과 유지 반응 구조만 맞으면 동작한다.

## 대안

- (A) MICOM 내 숙주: public API로 불가능해 제외. 비공개 API 사용은 MICOM 위임 원칙(정확 고정, public API만)과 충돌.
- 숙주를 커뮤니티 목적함수에 포함: 숙주 목적이 미생물 성장 최적화를 왜곡하므로 제외.

## 결과

- 숙주와 미생물이 한 최적화로 공동 최적화되지 않는다. 숙주 viability를 조합 탐색의 목적에 결합하는 기능은 없다.
- 결합 flux 해석에 양쪽 gDW 기준(biomass basis)이 필수가 되었다.
- 숙주 목적이 최적이어도 전달량이 한 점으로 정해지지 않을 수 있어, 전달 점값을 null로 두고 구간을 보고하는 규칙이 필요해졌다.
- 실제 스케일(10k+ 반응) 성능과 생물학적 정량 타당성은 Recon3D 같은 실제 숙주 모델로 따로 확인해야 한다.
