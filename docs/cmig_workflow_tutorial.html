CMIG Workflow Tutorial

A verified, scenario-based guide to community metabolic interaction analysis with CMIG: model review, consortium search, strain growth, abundance sweeps, gene knockouts, host–microbe coupling, community solves, dynamics, spatial preview, parameter sweeps, and statistics.

Commands and example outputs below were run against the five GEMs shipped in models/ (iAF987, iHN637, iML1515, iSFV_1184, iYO844) with Gurobi 12 and MICOM 0.39.0.

0. How CMIG Works (mental model)

CMIG is a product layer around MICOM. MICOM owns the community construction and the cooperative-tradeoff solve; CMIG owns everything around it that turns a raw solve into a reproducible, interpretable analysis:

  • MICOM does: build a community from member GEMs, apply abundances and medium, run the cooperative-tradeoff QP, return member/community growth and fluxes.
  • CMIG adds: model-pool search, per-strain growth reports, abundance sweeps, gene/reaction knockout screening, host coupling, sign normalization, tidy Parquet outputs, run hashes and manifests, diagnostics, and publication figures.

Two equivalent entry points cover the same analyses: a CLI (best for scripting, automation, and LLM agents) and a desktop GUI (PySide6/Qt). Every working GUI surface has a matching CLI command — see §12.

1. Installation & verification

CMIG expects you to supply your own GEM files. It does not download or curate AGORA, VMH, Recon, Human-GEM, or BiGG model collections.

git clone https://github.com/jyryu3161/CMIG.git
cd CMIG
uv sync --extra engine --extra gui --extra render --extra stats

For a smaller headless install without GUI/stats:

uv sync --extra engine --extra render

Verify the toolchain:

uv run cmig version
uv run cmig solvers        # capability matrix: gurobi (LP/QP/MILP), highs (LP/MILP), osqp (LP/QP)
uv run cmig golden verify  # MICOM-version regression gate — runs a real fixture solve
uv run ruff check cmig tests
uv run mypy cmig
uv run pytest -q
Expected: ruff clean, mypy clean (strict), pytest green (425 test functions), and golden verify reporting both solvers match the golden MICOM version.
Gurobi is required for the full-flux workflows (host-microbe, search, community FVA). Place a valid gurobi.lic in your home directory. The osqp path is available for QP-only approximate community solves, but its flux report is labelled qp_only_approximate and community FVA is not supported on osqp.

2. Launching the GUI

Start the desktop app with the console script or the CLI subcommand:

cmig-gui --lang en            # console script (installed by uv sync)
uv run cmig gui --lang ko     # or via the CLI subcommand
uv run python -m cmig.gui     # or the module entry point

--lang en|ko selects the UI language; --width/--height set the initial window size. All three resolve to the same launcher.

The default window has a Project Explorer (left), five primary tabs (center), and a Jobs panel (right):

The Show Advanced Tools toolbar button reveals lower-level tabs. These are now wired to real compute: Community Builder assembles a member folder + abundances and runs a community solve; Sweep View launches a sweep and shows the cache-hit column; Medium Editor has a Check-Growth button; Scenario Compare diffs two completed run directories.

3. Prepare your model pool

Put microbial SBML/XML (or JSON/MAT) models in one folder:

models/
  iHN637.xml      # Clostridium ljungdahlii (acetogen)
  iML1515.xml     # Escherichia coli K-12
  iYO844.xml      # Bacillus subtilis
  ...

If each strain sits in its own subfolder (strainA/model.xml), add --recursive to CLI pool commands. Always sanity-check imports first (§4).

4. Review a model before you trust it

Question: does this GEM import cleanly, and what is its exchange namespace status?

uv run cmig model-review --model models/iML1515.xml --out runs/review_iML1515

model_review.json reports model stats, inferred origin, warnings, and a namespace draft. Live example (iML1515):

reactions / metabolites / genes / exchanges2712 / 1877 / 1516 / 331
source_formatsbml
namespace.blockedtrue
namespace.coverage_pct0.0
Do not panic at "blocked": true, coverage 0%. The namespace hard-gate (spec §4.8) is designed to block a community solve when high-confidence exchange mappings are unresolved — but model-review produces a draft with no known targets, so every metabolite is reported "unresolved". In practice the community workflows (strain-growth, search, …) run with an empty decision set and are not blocked. So this field is advisory only. It also means the gate provides no protection against genuine mixed-namespace pools by default — if you combine models from different namespace conventions, verify the exchange IDs match yourself.

5. Scenario A — strain-specific growth strain-growth

Question: how does each model grow alone, and how does it grow inside the full MICOM community?

uv run cmig strain-growth --model-dir models --out runs/strain_growth

Live example (2-member pool iHN637 + iML1515):

membersingle_growthcommunity_member_growthabundance
iHN6370.22450.75100.5
iML15150.87700.75100.5

single_growth is standalone FBA growth (the 0.877 for iML1515 is the textbook E. coli aerobic-glucose value). community_member_growth is growth after community construction and cooperative tradeoff. In the GUI: Search tab → pick the folder → Strain Growth.

6. Scenario B — best model combination for a target search

Question: which 2-member combination produces the most acetate?

uv run cmig search \
  --model-dir models \
  --target ac \
  --min-size 2 --max-size 2 \
  --top-k 10 --strategy auto \
  --out runs/search_acetate

Live example (best pair): iHN637 + iML1515, acetate flux 26.50, community growth 0.751, target exchange resolved to EX_ac_m.

Useful outputs: search_rankings.csv, search_member_matrix.csv, pool_diagnostics.csv, search_plot.svg, search_scatter.svg, search_summary.json. Use --recursive for subfolder pools.

Honest target handling. If a target exchange is absent from the candidate models, the run reports it as missing rather than a false zero. For butyrate (--target but) on an E. coli + acetogen pool you should expect missing — neither organism secretes butyrate. Check pool_diagnostics.csv (n_with_target_exchange) before interpreting a ranking.

Multi-target search

Rank combinations against several targets at once with --targets (plus optional --target-weights):

uv run cmig search \
  --model-dir models \
  --targets ac,for --target-weights 2,1 \
  --min-size 2 --max-size 2 \
  --out runs/search_ac_for

Give each target its own direction with --target-directions (e.g. maximize acetate but minimize a toxin: --targets ac,tox --target-directions max_secretion,min_secretion); without it every target uses --direction. Each combination is scored per target, each score normalized to [0,1] over the observed range and combined by the weighted sum; for exactly two targets, non-dominated combinations get a pareto=True flag. Live example (ac + formate, weights 2:1): best pair iHN637+iML1515 (ac 26.5, formate 80.6, weighted score 3.0, Pareto-optimal). search_rankings.csv gains flux_<t>/score_<t> columns and a pareto flag. Combinations missing any target exchange are excluded from ranking with an explicit diagnostic (never a false zero). Multi-target search is exhaustive-only and errors rather than silently truncating an oversized candidate set.

7. Scenario C — rank gene/reaction knockouts gene-ko-search

Question: within a fixed consortium, which single-gene knockout in one member most changes target production?

uv run cmig gene-ko-search \
  --model-dir models \
  --members iML1515,iHN637 \
  --member iML1515 \
  --target ac \
  --max-genes 0 \
  --top-k 20 \
  --out runs/gene_ko_ac
OptionMeaning
--memberKnock out genes in one named member. Omit to screen every member (screening_scope: all_members).
--ko-level gene|reactionKnock out genes via GPR (default) or reactions directly. Automatic reaction enumeration skips exchanges and the biomass/objective reaction.
--gene-selection id|random + --seedHow targets are picked when not listed explicitly. Deterministic either way.
--max-genes N0 = evaluate all. If a smaller N truncates the set, the run records an explicit warnings entry and n_genes_total.
--jobs NWorker threads. Results are independent of --jobs; validate solver thread-safety before relying on >1.
Transparency is built in. A capped screen never pretends to be complete. Live example with --max-genes 6 emitted: "iML1515: evaluated 6 of 1516 genes (selection=id); raise --max-genes (0=all) for full coverage". Outputs: gene_ko_summary.json (baseline flux, warnings, ko_level, selection, seed, n_genes_total, ranked KOs), gene_ko_rankings.csv, gene_ko_plot.svg/.tiff.

8. Scenario D — one-strain abundance sweep abundance-impact

Question: if one strain becomes more abundant, does its influence on acetate rise?

uv run cmig abundance-impact \
  --model-dir models \
  --member iML1515 \
  --fractions 0.25,0.5,0.75 \
  --target ac \
  --out runs/iML1515_ac_ratio

CMIG sets the selected member to each fraction and rescales the others to fill the remainder; MICOM recomputes growth and fluxes per condition. Live example:

iML1515 abundancecommunity growthmember acetate exchangecommunity acetate exchangeinfluence share
0.250.7320.0016.470.00
0.500.7510.321.140.14
0.750.7290.550.450.77
Read this as a controlled sensitivity analysis, not ecological causality. Note the non-monotone community acetate: raising iML1515 increases its own acetate share (0→0.14→0.77) while total community acetate falls — a cross-feeding shift worth inspecting, not optimizing on influence share alone. Outputs: abundance_impact.csv, member_growth_by_abundance.csv, abundance_impact_plot.svg/.tiff.

9. Scenario E — host–microbe coupling host-microbe-bigg

Question: which microbial secretions can a Recon/Human-GEM-style host directly consume?

uv run cmig host-microbe-bigg \
  --host /path/to/Recon3D.xml \
  --model-dir models \
  --recursive \
  --out runs/host_microbe

This assumes compatible BiGG-style exchange identifiers; CMIG does not perform Recon-specific interface curation. Outputs include microbial_secretion.csv, host_uptake.csv, microbe_to_host.csv, interaction_edges.csv, interaction_matrix.csv, member_contribution.csv, and figures (interaction_circle/heatmap/bubble.svg, member_contribution.svg).

A synthetic smoke test is available with no host GEM: uv run cmig host-fixture --out runs/host_fixture (self-labelled scope: synthetic_toy_host_not_human_gem_quantitative). The host is held to a viability/maintenance lower-bound constraint and is not added to the community objective (spec §12). If the host FBA is infeasible under coupling it is reported honestly as host_status: infeasible rather than silently succeeding.

Mapping wizard (pre-flight) host-map

Before coupling, check which microbial secretions the host can actually consume:

uv run cmig host-map --host /path/to/Recon3D.xml --model-dir models --out runs/host_map

It classifies every secretable microbial metabolite as exact (same BiGG id, directly consumable), normalized (matches only after id normalization — review before trusting), or unmatched (no host counterpart). Outputs: host_map_summary.json, host_exchange_map.csv, and a starter host_interface_map.json you can edit. Live example (iML1515 as host + 2 microbes): 331 exact / 0 normalized / 21 unmatched of 352 secretions.

10. Scenario F — a MICOM taxonomy solve solve

If you already have a MICOM-compatible taxonomy CSV:

uv run cmig solve \
  --taxonomy /path/to/taxonomy.csv \
  --medium medium_presets/western_diet.csv \
  --solver gurobi \
  --tradeoff-f 0.5 \
  --out runs/solve

Or run the built-in fixture: uv run cmig solve-fixture --solver gurobi --out runs/solve_fixture. Outputs: nodes.parquet, edges.parquet, profile.parquet, manifest.json.

Solver provenance is explicit. The manifest records the growth solver, flux solver, and flux report status. Live fixture example:
solvergrowth_solverflux_solverflux_report_status
gurobigurobigurobifull
osqposqpnullqp_only_approximate
The same inputs produce identical run hashes across machines and months (fixture gurobi 29844e29…, osqp c491a6a8…), so cached and published results stay comparable.

11. Scenario G — well-mixed dFBA dfba

Static-optimization dFBA (Mahadevan 2002): each step updates uptake bounds from extracellular concentrations, solves FBA, and advances biomass + metabolites with non-negativity enforced.

uv run cmig dfba \
  --model models/iML1515.xml \
  --dt 0.1 \
  --t-end 5.0 \
  --out runs/dfba_iML1515

With no --initial, CMIG uses an aerobic default where available (EX_glc__D_e=10, EX_o2_e=20, EX_ac_e=0, EX_lac__D_e=0). Explicit --initial values are strict and must exist in the model. Live example (short horizon) completed with status: completed, 16 timepoints, tracking those four exchanges. Outputs: dfba_summary.json, timecourse.parquet, dfba_timecourse.csv, dfba_timecourse.svg/.tiff.

Scope: well-mixed single-model only. When a substrate is exhausted mid-step, both flux and biomass are scaled by the limiting-substrate fraction so mass balance holds (no growth on phantom substrate). Full spatial community dFBA is out of scope.

12. Scenario H — spatial medium preview spatial-preview

A lightweight, COMETS-inspired 2D diffusion/source-sink design tool. It does not solve FBA on each grid cell — use it to check gradient settings before heavier analyses.

uv run cmig spatial-preview \
  --metabolite EX_glc__D_e \
  --width 48 --height 48 \
  --source-edge left --sink-edge right \
  --steps 120 \
  --out runs/spatial_glucose

Live example completed with a glucose gradient (source value 10 → sink 0), 7 stored frames. Outputs: spatial_summary.json, spatial_frames.csv, spatial_heatmap.svg/.tiff, spatial_snapshots.svg/.tiff.

13. Scenario I — parameter sweeps sweep

Sweep any of six axes (medium_variant, abundance, member_set, bounds, tradeoff_f, solver) into a long-format sweep.parquet, one condition per row, with a run hash and an ok/failed status per condition.

# fixture demo (tradeoff_f axis):
uv run cmig sweep-fixture --out runs/sweep_fixture

Live example produced two rows for tradeoff_f = 0.3 and 0.5 with two distinct run hashes — confirming the reproducibility axis (including the bounds axis) actually varies the hash. Failed conditions are recorded with a diagnostic rather than dropped.

cmig sweep now caches by a content signature equivalent to the run-hash components, so a content-identical condition replays instead of re-solving (its row shows cache_hit=true with the same run_hash and value). Deterministic failures are cached too. Distinct conditions correctly show cache_hit=false.

14. Scenario J — statistics on sweep results stats-sweep

Distribution summaries, effect sizes (Cliff's δ, Cohen's d), MWU/Welch/Kruskal/ANOVA, and BH/BY FDR correction — with misuse warnings.

uv run cmig stats-demo  --out runs/stats_demo          # deterministic 2-group demo
uv run cmig stats-sweep --sweep runs/sweep_fixture/sweep.parquet --out runs/stats_sweep

Live stats-demo produced summary, test, fdr_qvalues, and warnings keys. Embedding methods (PCA/KMeans/UMAP) are available in the stats extra.

15. Scenario K — constraint sandbox (preview vs commit) sandbox-fixture

Change a reaction's bound and re-optimize the community, comparing baseline vs constrained profiles. A preview is ephemeral; only commit promotes it to a reproducible run.

# preview (ephemeral — no manifest, no run hash):
uv run cmig sandbox-fixture --reaction EX_glc__D_e__Escherichia_coli_1 --lower -8 --upper 1000 \
  --out runs/sandbox_preview

# commit (promotes to a durable run):
uv run cmig sandbox-fixture --reaction EX_glc__D_e__Escherichia_coli_1 --lower -8 --upper 1000 --commit \
  --out runs/sandbox_commit

Live example: the preview wrote only sandbox_summary.json; the commit added nodes/edges/profile.parquet + manifest.json with run hash 3494f654…. This is the §4.8 preview-vs-commit guarantee — experimenting never pollutes your reproducibility store.

16. CLI for LLM agents & automation

Agents should start from the machine-readable workflow map, then inspect finished runs in a stable JSON shape:

uv run cmig workflows --format json                                   # 14 GUI→CLI workflow entries
uv run cmig inspect-run --run-dir runs/search_acetate --format json   # kind, status, run_hash, summary, artifacts

inspect-run detects known summaries (search_summary.json, host_microbe_bigg_summary.json, dfba_summary.json, spatial_summary.json, manifest.json) and reports the workflow kind, status, run hash, summary keys, and artifacts — the CLI counterpart to opening a run in the GUI Profile view.

Publication figures render-figure

Render a completed run's tidy profile to a publication figure with the R (ggplot2) renderer, with an automatic matplotlib fallback:

uv run cmig render-figure --run-dir runs/solve --out runs/solve/profile.svg \
  --renderer auto --format svg --title "Community profile"

--renderer auto uses R when Rscript is available and falls back to matplotlib on any R failure (e.g. missing .Rlib packages); r forces R (hard error on failure) and matplotlib forces the fallback. Formats: svg|tiff|pdf|eps. A <out>.figure_spec.json sidecar (seed, dims, preset) is written for reproducibility.

17. Reproducibility & provenance

  • run_hash combines model/medium checksums, member set, abundances, bounds, tradeoff f, solver setting, MICOM version, CMIG core version, namespace decisions, and flux normalization. Change any of these and the hash changes; change none and it is byte-identical.
  • Solver labels are honest: gurobi → full, osqp → qp_only_approximate (with flux_solver: null).
  • Manifests record solver/flux status, software versions, platform, and env lock.
  • Golden gate: cmig golden verify blocks promotion if the installed MICOM version diverges from the golden baseline.

18. Scope & honest limitations

  • You provide your own GEM files; CMIG never auto-downloads model collections.
  • The namespace hard-gate is inert on the default community path (no auto-reconciliation producer), so model-review's "blocked" is advisory — verify mixed-namespace pools yourself.
  • Host-microbe coupling is BiGG-style direct exchange matching only (no interface mapping wizard).
  • dFBA is well-mixed single-model; spatial-preview is medium design only (no per-cell FBA).
  • The R (ggplot2) profile renderer is wired via cmig render-figure (with a matplotlib fallback); the multi-panel R figures (ggraph/ComplexHeatmap/circlize) are still produced by the per-workflow matplotlib helpers.
  • Multi-target search is exhaustive-only (no heuristic strategy for very large candidate sets).
  • Minimal-medium selection is deterministic for a fixed solver on a fixed machine; among equicardinal alternate optima, cross-solver selection may differ (documented).

19. Recommended review checklist

  1. Confirm every model imports cleanly (pool_diagnostics.csv, n_readable).
  2. Confirm the target exchange exists in candidates (n_with_target_exchange) before trusting a ranking.
  3. Compare single_growth vs community_member_growth to see who benefits/loses from the community.
  4. For abundance sweeps, read both target_influence_share and community_growth — don't optimize influence alone.
  5. For gene-KO, check the warnings and n_genes_total to confirm coverage (use --max-genes 0 for full screens).
  6. Check the manifest's solver label before comparing numbers across runs (full vs qp_only_approximate).
  7. Export SVG for inspection, then use the CSV/Parquet tables for final manuscript plotting.

This tutorial's commands and example numbers were verified end-to-end against the shipped models on 2026-07-09 (Gurobi 12, MICOM 0.39.0). Your absolute flux values will depend on your medium, model set, and solver.
