CMIG Workflow Tutorial

An operational guide to the complete CMIG CLI: model review, community solves, exhaustive and genetic-algorithm consortium search, host workflows, dFBA sensitivity, publication preflight, reproducibility, and run inspection.

Refreshed against the live top-level and per-command help and cmig workflows --format json on 2026-08-24. Treat cmig <command> --help as authoritative when this page and an installed build differ.

0. Start from the live contract

uv run cmig version
uv run cmig solvers
uv run cmig --help
uv run cmig workflows --format json
uv run cmig <command> --help

The top-level help currently exposes 35 commands. The workflow map contains 15 GUI-to-CLI routes and intentionally lists common options, not every answer-determining flag. Always read the selected command's help before a scientific run.

Preflight before a long solve. The full-flux search and host workflows require Gurobi. solvers reports capabilities separately from availability; a listed solver is not necessarily licensed or selectable by every command.

1. Install and verify

CMIG expects user-supplied GEMs and never downloads AGORA, VMH, Recon, Human-GEM, or BiGG collections automatically.

uv sync --all-extras --group dev
uv lock --check
uv run ruff check .
uv run mypy cmig
uv run cmig golden verify-envelope
uv run cmig golden verify
uv run pytest -q

golden verify-envelope is license-free and protects workflow-manifest serialization. golden verify is the solver/MICOM numeric gate and belongs in the licensed environment.

3. Review models and namespaces

uv run cmig model-review \
  --model /path/to/model.xml \
  --out runs/model_review

uv run cmig model-quality \
  --model-dir /path/to/models \
  --out runs/model_quality

uv run cmig namespace-suggest \
  --model /path/to/model.xml \
  --known-targets known_targets.txt \
  --out runs/namespace_suggestion

namespace-suggest produces a decision draft; it does not silently reconcile a mixed-namespace pool. Review the output before using it as a namespace decision.

4. Solve a MICOM community

uv run cmig solve \
  --taxonomy /path/to/taxonomy.csv \
  --medium /path/to/medium.csv \
  --solver gurobi \
  --tradeoff-f 0.5 \
  --out runs/community

Outputs include manifest.json, nodes.parquet, edges.parquet, and profile.parquet. A medium id with no model counterpart is an input error by default.

--allow-unknown-medium is a diagnostic relaxation. It drops unmatched nutrients, names them, and continues with status: degraded. It is available on solve, search, strain-growth, abundance-impact, gene-ko-search, sweep, host-microbe-bigg, host-search-bigg, and host-ko-impact. Do not use a partially applied medium for a reported result.

5. Search model combinations search

Single target: exhaustive, random, or GA

uv run cmig search \
  --model-dir /path/to/models \
  --target ac \
  --min-size 2 --max-size 6 \
  --strategy ga --seed 20260824 \
  --ga-pop-size 60 \
  --ga-generations 40 \
  --ga-mutation-rate 0.2 \
  --ga-immigrant-fraction 0.1 \
  --ga-tournament-k 3 \
  --ga-elitism 2 \
  --ga-max-evaluations 1500 \
  --ga-patience 8 \
  --top-k 20 \
  --out runs/search_ac_ga
  • --strategy auto uses exhaustive search up to --exhaustive-max combinations and GA above that threshold for a single target.
  • --strategy random evaluates --n-samples combinations.
  • GA controls and --robustness-fva are single-target options. The seed makes stochastic selection reproducible; the evaluated candidates and stop reason remain part of the run record.

Exercise the same advanced search path on bundled fixtures with:

uv run cmig search-advanced-fixture \
  --strategy ga --min-size 2 --max-size 3 --seed 20260824 \
  --out runs/search_advanced_fixture

Several targets: report the trade-off

uv run cmig search \
  --model-dir /path/to/models \
  --target-preset scfa \
  --multi-metric pareto \
  --min-size 2 --max-size 3 \
  --top-k 20 \
  --out runs/search_scfa_pareto

The default normalized_weighted, carbon_equivalent, and raw_sum modes are linear scalarizations and can select a single-metabolite specialist. pareto returns the non-dominated trade-off set. Its rank is a reporting order, not a claim that the first point dominates the rest. --robustness-fva is accepted but silently inert in multi-target mode.

6. Growth, abundance, and knockout workflows

Controlled strain-growth comparison

uv run cmig strain-growth \
  --model-dir /path/to/models \
  --single-medium community \
  --out runs/strain_growth

--single-medium community projects the community medium onto each member. model_default reports native capability and must not be interpreted as a cross-feeding effect. Check medium_metabolites_unavailable_to_member per row.

Abundance sensitivity

uv run cmig abundance-impact \
  --model-dir /path/to/models \
  --member iML1515 --fractions 0.1,0.25,0.5,0.75 \
  --target ac --fva \
  --out runs/abundance_ac

This is sensitivity, not causality. Use --fva to distinguish a trend from alternate-optimum variation.

Gene or reaction knockout ranking

uv run cmig gene-ko-search \
  --model-dir /path/to/models \
  --members iML1515,iHN637 \
  --member iML1515 --target ac \
  --max-genes 0 --rank-by effect \
  --medium /path/to/medium.csv \
  --out runs/gene_ko_ac

--max-genes 0 requests a complete screen. --rank-by effect ranks by absolute change; remaining ranks by remaining flux. The command accepts both --medium and --allow-unknown-medium.

7. Host workflows

Use host-generic for a generic host smoke solve and host-benchmark for the benchmark summary. Both accept --model, --solver gurobi, and --out:

uv run cmig host-generic --model /path/to/Recon3D.xml --out runs/host_generic
uv run cmig host-benchmark --model /path/to/Recon3D.xml --out runs/host_benchmark

Inspect objective_warning, n_boundary_reactions, and n_nonexchange_boundary_uptake. A shipped maintenance or transport objective is not a growth objective.

Review the interface first

uv run cmig host-map \
  --host /path/to/host.xml \
  --model-dir /path/to/models \
  --out runs/host_map

Annotation matches are candidates. Resolve every needs_review entry—especially D/L stereoisomers—before publication. --accept-unreviewed-map is a recorded waiver, not a substitute for review.

Couple, rank, or perturb

export MICROBIAL_BIOMASS_GDW="<study microbial dry mass in gDW>"
export HOST_BIOMASS_GDW="<host dry-mass basis in gDW>"
export BIOMASS_BASIS_SOURCE="<measurement record or literature citation>"

uv run cmig host-microbe-bigg \
  --host /path/to/host.xml --model-dir /path/to/models \
  --host-objective BIOMASS_reaction \
  --microbial-biomass-gdw "$MICROBIAL_BIOMASS_GDW" \
  --host-biomass-gdw "$HOST_BIOMASS_GDW" \
  --biomass-basis-kind measured \
  --biomass-basis-source "$BIOMASS_BASIS_SOURCE" \
  --interface-map runs/host_map/host_interface_map.json \
  --out runs/host_microbe

uv run cmig host-search-bigg \
  --host /path/to/host.xml --model-dir /path/to/models \
  --target ac --metric target_transfer \
  --microbial-biomass-gdw "$MICROBIAL_BIOMASS_GDW" \
  --host-biomass-gdw "$HOST_BIOMASS_GDW" \
  --biomass-basis-kind measured \
  --biomass-basis-source "$BIOMASS_BASIS_SOURCE" \
  --interface-map runs/host_map/host_interface_map.json \
  --out runs/host_search

uv run cmig host-ko-impact \
  --host /path/to/host.xml --model-dir /path/to/models \
  --member iML1515 --ko-level reaction --reactions ACKr --target ac \
  --host-objective BIOMASS_reaction \
  --microbial-biomass-gdw "$MICROBIAL_BIOMASS_GDW" \
  --host-biomass-gdw "$HOST_BIOMASS_GDW" \
  --biomass-basis-kind measured \
  --biomass-basis-source "$BIOMASS_BASIS_SOURCE" \
  --interface-map runs/host_map/host_interface_map.json \
  --out runs/host_ko_ackr
Host coupling closes all undeclared boundary uptake by default. Passing --keep-host-uptake changes the question: apparent host benefit may come from the background host medium rather than microbes. Always choose the host objective explicitly and inspect boundary_isolation_policy and host_isolation_policy.

8. dFBA and numerical sensitivity

uv run cmig dfba \
  --model /path/to/model.xml \
  --initial EX_glc__D_e=10,EX_o2_e=20,EX_ac_e=0,EX_lac__D_e=0 \
  --close-untracked-uptake \
  --dt 0.1 --t-end 5 \
  --out runs/dfba

uv run cmig dfba-sensitivity \
  --model /path/to/model.xml \
  --initial EX_glc__D_e=10,EX_o2_e=20,EX_ac_e=0,EX_lac__D_e=0 \
  --close-untracked-uptake \
  --dts 0.2,0.1,0.05 --kms 0.005,0.01,0.02 \
  --out runs/dfba_sensitivity

Without --close-untracked-uptake, substrates omitted from --initial can feed growth without a tracked concentration or Km constraint. With it, the initial list must contain every intended nutrient. Read acceptance.interpretable and not_interpretable_because; a written grid is not necessarily a valid endpoint.

spatial-preview simulates a medium diffusion/source/sink design only. It does not solve FBA in grid cells.

9. Publication benchmark

uv run cmig publication-benchmark --help
uv run cmig publication-benchmark \
  --model-dir /path/to/models \
  --assume-bigg-namespace \
  --search-target ac \
  --dfba-model /path/to/model.xml \
  --host /path/to/host.xml \
  --host-interface-map /path/to/reviewed_host_interface_map.json \
  --microbial-biomass-gdw "$MICROBIAL_BIOMASS_GDW" \
  --host-biomass-gdw "$HOST_BIOMASS_GDW" \
  --biomass-basis-kind measured \
  --biomass-basis-source "$BIOMASS_BASIS_SOURCE" \
  --out runs/publication_benchmark

The integrated command has a broad option surface, so do not infer its inputs from the workflow map. Its dFBA leg does not expose --close-untracked-uptake; when a dFBA endpoint is load-bearing, archive a separate, interpretable dfba-sensitivity run. Follow docs/PUBLICATION_VALIDATION.md for the release rerun and evidence labels.

10. Sweeps, statistics, sandbox, and fixtures

uv run cmig sweep --taxonomy taxonomy.csv \
  --tradeoff-fs 0.3,0.5 --mediums /path/to/medium.csv \
  --out runs/sweep

uv run cmig stats-sweep \
  --sweep runs/sweep/sweep.parquet \
  --out runs/stats_sweep

uv run cmig sandbox-fixture \
  --reaction EX_glc__D_e__Escherichia_coli_1 \
  --lower -8 --upper 1000 --commit \
  --out runs/sandbox_commit

Fixture commands—solve-fixture, search-fixture, search-advanced-fixture, dfba-fixture, host-fixture, sweep-fixture, sandbox-fixture, and stats-demo—exercise operational paths. Their synthetic outputs are software validation, not biological evidence. A deterministic sweep grid is not a biological replicate.

11. Exit codes, inspection, and two fingerprints

ExitMeaning
0The command completed scientifically, or a supported --allow-failed-run explicitly waived exit 3.
2Input or argparse error, including passing a flag that command does not support.
3Artifacts were written but the scientific solve failed, or inspect-run found an integrity mismatch.
 
uv run cmig inspect-run --run-dir runs/example --format json
  • run_hash fingerprints inputs. It does not certify the answer.
  • result_digest fingerprints declared artifact bytes. A fresh solve manifest does not record one; read result_digest_absent_reason.
  • status_source says where the run verdict came from. Treat unknown or unrecognized statuses as not-ok.
  • Presence of output files is not success. Check the analysis command's exit code before interpreting inspect-run.

12. Scope and honest limitations

  • The bundled microbial pool is a methods fixture, not a representative gut community.
  • Host annotation maps require scientific review; direct matching is not biological ground truth.
  • Host biomass values require an explicit measured or literature basis for publication.
  • dFBA is well-mixed and single-model; spatial-preview is not spatial community FBA.
  • edges.parquet.weight is a per-taxon flux, not an abundance-weighted community contribution.
  • Parquet and figure writers are not yet atomic.

This page deliberately avoids freezing solver-derived example values. Archive the command, manifest, dependency versions, exit code, run_hash, and result_digest for every reported analysis.
